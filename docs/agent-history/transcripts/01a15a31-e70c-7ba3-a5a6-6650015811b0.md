**可以朝“后台运行、无需添加游戏列表”的方式实现，但目前 0.2.1 还做不到。对这两个 mod，已有比完整模拟 SR Service 更直接的实现入口。**

我核对了它们使用的 SR-lib：它通过 `LoadLibraryW("SimulatedRealityDirectX.dll")` 等名称加载运行库，没有写死安装路径。因此可以做成：

1. 一次性配置桥接运行库的加载路径。
2. TitanLeiaBridge 在后台管理屏幕、眼追和镜片。
3. 游戏正常从 Steam 或快捷方式启动，开启 LeiaSR 时自动加载桥接运行库。

这样就不需要逐个添加游戏，也不需要逐个注入。**不过加载路径必须正确生效**：游戏自带的原厂 DLL、已经加载的 DLL 或游戏自己设置的搜索规则，可能优先于配置路径，不能保证覆盖所有 LeiaSR 程序。[Windows DLL 搜索规则](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order)

至于你说的“模拟 SR Service”，它与上述方案有区别：**游戏进程内的 Leia runtime 仍负责交织渲染**，后台服务不能仅靠发送眼位就自动把它变成 BOE 交织。要完全保留原版 runtime、只替换服务，还需要确认服务协议能否提供 BOE 所需的光学模型或渲染配置，目前没有验证这一点。

**我建议下一版采用“统一加载桥接 runtime＋后台设备服务”。** 这最接近你要的使用体验，也能复用已经验证的 BOE 交织和双眼数据。真正 Leia 显示器与泰坦屏需要同时使用时，还要增加后端选择，避免全局加载配置把原厂 Leia 路径也切到泰坦桥接。
