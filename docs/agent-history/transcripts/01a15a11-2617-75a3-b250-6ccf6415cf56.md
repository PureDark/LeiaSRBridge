## 2026-10-20T16:07:15.740Z · assistant

两者使用同一套 SDK，区别是选取的数据范围：

| 接口 | LeiaSR 提供的数据 |
|---|---|
| `HeadPose` | 头部 XYZ 位置、pitch/yaw/roll 旋转 |
| `Head` | 上述姿态，以及左右眼、左右耳的三维位置 |
| `EyePair` | 左右眼三维位置 |

各流还包含帧号和时间戳。位置单位是毫米，旋转是弧度。

FallenFlower3D 只用位置跟随，因此选 `HeadPose`；Yakuza 还需要双眼位置做跟踪投影，因此选 `Head`。只做位置跟随时，两种接口都可以。

**[0.2.0 已编译打包，点击获取](F:/目标软件/ModexLite/TitanLeiaBridge/dist/TitanLeiaBridge-0.2.0-win64.zip)**：

- 删除旁路及无用诊断，按你的实测将移动串扰标记为已修复。
- 默认 **+8.0 mm / 40 ms**，保留全局快捷键，调整自动保存。
- 接通两个 mod 的 **XYZ 位置头追**；BOE COM 没有旋转和真实双眼数据，因此这些功能仍不可用，Yakuza 的双眼跟踪投影暂不支持。
- 9 项离线检查通过，MCU 标定未改。退出旧版和游戏，完整解压新版，在 mod 中开启头部跟随后测试。

关键发现：

- **官方 SDK 已有分别测得的双眼 XYZ**，位于168字节结果的偏移12、24；当前 COM 通道丢掉了它们。
- 两眼来自双相机三角测量，但定位点是**各16个眼睑轮廓点的平均**，不是虹膜中心或视线。索引与 MediaPipe 官方右/左眼拓扑吻合；实际镜像关系仍需遮眼验证。
- **BoeLandmark.dll 实际产生468个二维面部关键点**。公开结果仅保留5点/相机，内部另选9点做PnP。
- **原厂内部已有三个旋转角计算**：`0x1800B24E0`调用solvePnP，输出弧度/角度和旋转矩阵；调用者只把一个平均角按±8°转换为状态字节，其余结果未公开。
- 没有找到真实耳部测量或虹膜/视线输出。脸轮廓不能直接作为耳位。

最小方案是保留官方 FaceTracking.exe 采集，在私有 SDK 代理中截获完整168字节并发布扩展IPC。旋转可先截获原厂PnP输出进行验证；长期更适合取得9点或468点，自行求解并检查重投影误差、坐标系和有效性。原厂模板/点序仍需验证，不能把现有内部角度直接称为可靠6DoF。
