# LeiaSRBridge 0.9.1

开发者入口：[构建、目录与打包说明](docs/BUILD.zh-CN.md) · [Agent 开发记录](docs/agent-history/README.md) · [HTML 设计稿](design/titan-bridge-opus5.5.html)

面向京东方（BOE）裸眼 3D 显示器的独立 LeiaSR 转接器，支持使用兼容 BOE / DepthTransformerPlus 底层方案的显示器，包括泰坦军团、雷神；ViewX 暂不支持。支持 SDK 1.34.10、Windows x64，含现代 DX12 与 Odyssey 使用的旧版 DX11/DX12 接口。直接使用 FallenFlower3D 和 YakuzaVRMod 已生成的左右眼图像，不修改游戏或 mod 文件。

本机项目目录：`F:\开发项目\LeiaSRBridge`；局域网共享：`\\PUREDARK-GAMING\LeiaSRBridge`。共享权限与账户不变，其他电脑请更新项目工作目录。

## 显示器兼容性

支持范围以 **BOE / DepthTransformerPlus 的设备控制、眼位追踪和交织方案兼容**为准，不限显示器品牌；仅使用京东方裸眼 3D 面板，并不足以确认兼容。

| 品牌 / 设备 | 当前支持情况 | 验证情况 |
|---|---|---|
| 泰坦军团 M27E6V-3D | 支持 | 已实机验证 |
| 雷神裸眼 3D 显示器（使用本次分析的 DepthTransformerPlus 方案） | 支持现有桥接，无需另写适配 | 配套软件核心组件与现有后端完全一致，实体屏待验证 |
| 其他采用相同 BOE / DepthTransformerPlus 底层方案的裸眼 3D 显示器 | 可使用现有桥接，具体型号需确认兼容 | 未逐型号验证 |
| ViewX 裸眼 3D 显示器 | **暂不支持** | 已分析的软件使用不同的 LF3D 交织路径，适配暂缓 |

兼容性依据：[雷神分析记录](RE/thunderobot_compatibility_analysis.md) · [ViewX 分析记录](RE/viewx_compatibility_analysis.md)。

## 从 TitanLeiaBridge / Stereo3DBridge 升级

1. 退出旧桥接程序、Hub 和游戏，将新版包内文件覆盖到**原来的安装目录**。保留 settings.ini、games.txt 和 vendor 目录结构，无需重填水平补偿、预测、运行模式或游戏列表。
2. 启动 LeiaSRBridge.exe。新版不包含 TitanLeiaBridge.exe、Stereo3DBridge.exe 或旧测试程序；覆盖升级后请删除遗留的旧 EXE，并更新快捷方式。
3. 首次启动新版时，同目录的旧自启动项会迁移到 LeiaSRBridge 名称和新 EXE，并复制 Windows 启动审批状态，保留用户已禁用的状态。关闭自启动会清除本程序的新旧条目。
4. 原目录内 runtime 路径不变时，已有免列表接入继续识别，无需因改名再次提权。若换到其他目录，仍须在系统接入中更新路径一次，并重新启用自启动来更新位置。

主日志改为 logs/LeiaSRBridge.log，旧日志不删除。为兼容已登记的免列表接入、旧客户端和设备组件，内部保留 TitanLeiaRuntime.dll、原有 IPC/窗口类名、WebView 缓存和 Software\\TitanLeiaBridge\\RuntimeIntegration 注册表标识。它们属于兼容协议，不是遗漏的界面名称。历史发行包、逆向证据、设计原稿和 Agent 原始记录保留当时名称。

## 推荐单眼尺寸

- 原生 LeiaSR 预览的概览与诊断页显示原厂 SDK 推荐视图纹理宽高（px），每秒刷新；查询不可用时显示“暂不可用”。桥接模式不显示此项。
- Bridge 的 getRecommendedViewsTextureWidth / Height 返回主显示器原生宽高（Windows 显示目标首选模式）各除以 2，作为推荐单眼尺寸；例如 3840 × 2160 屏返回 1920 × 1080，左右并排纹理为 3840 × 1080，不使用桌面尺寸或 DPI 缩放后的尺寸；无法查询时返回 0。仍按既有使用要求，将兼容屏设为主显示器。

- 原有游戏列表保留为可选兼容入口。统一接入支持使用普通 DLL 搜索路径的 SDK 1.34.10 / x64 / DX12 客户端；游戏自带 SDK、硬编码绝对路径或自定义 DLL 搜索规则时不保证生效。

- 完整数据使用私有整包 IPC，校验眼追进程路径、PID 和创建时间；协议升级为 v2，退出游戏及旧桥接后完整解压，不混用版本。

## 使用

1. 退出游戏和旧版桥接程序，把新包完整解压到可写目录，例如 `D:\LeiaSRBridge`。迁移旧目录的 `games.txt`；后续升级也可以迁移 `settings.ini`。不要用旧 DLL 覆盖新包。
2. 不需要 DepthTransformerPlus，不需要注册 COM。关闭其他占用该屏 MCU 或摄像头的 3D 程序，再运行 `LeiaSRBridge.exe`。
3. 首次点击 **“启用免列表接入”**，允许 Windows 管理员提示；“免列表接入”显示“已启用”后，完全退出并重新打开 Steam 等游戏启动器。若启动器仍使用旧环境，注销并重新登录 Windows。这一步只配置一次，更换桥接目录/升级到新目录后再点一次。
4. 等待设备和校准就绪，点击“后台运行”，随后正常启动游戏，游戏内选择 **LeiaSR**。不需要添加游戏列表。头追需要在 mod 内开启其头部跟随选项，桥接器不会修改 mod 设置。
5. 关闭桥接窗口会隐藏到托盘；用右上角“更多 → 退出转接器”或托盘右键“退出”才能结束后台。之后使用时只需先启动桥接；可用 `LeiaSRBridge.exe --background` 直接隐藏运行。

配置作用于系统 PATH 中的桥接 runtime 路径，不覆盖原厂 DLL、不注册伪 SR Service、不停止原厂服务。配置会保留到显式恢复；桥接退出后，已选择桥接运行库的新游戏需要后台重新运行才能取得设备，不能自动切到原厂。

使用真实 Leia 显示器时，点击 **“恢复原厂接入”**，再重启游戏及启动器，恢复原有运行库搜索路径。机器未安装原厂 Leia 运行库时，此操作只停用桥接，不会安装原厂软件。当前通过切换配置选择后端，不支持同一游戏进程内同时为真实 Leia 屏与泰坦屏使用不同运行库。

Windows 已加载的同名 DLL、游戏目录中的 DLL 或自定义搜索路径可能优先。此时使用可选游戏列表的“启动游戏”，在入口前预加载桥接。列表自动接管默认关闭，只对列表中的游戏生效；“恢复原厂接入”后若手动重新开启列表接管，列出的游戏仍会使用桥接。

删除或移动桥接目录前先恢复原厂接入；更新到另一目录可直接在新版中点“启用”，程序会移除自己登记的旧条目并登记新目录，保留其他 PATH 内容。已运行的游戏不会热切换 DLL，必须退出重开。

未检测到人脸仍可启动和显示 3D。交织在短暂丢失时保持上次眼位，500 ms 后使用默认 `(0,0,600 mm)`，再加全局补偿；识别恢复后重新跟踪。头部运动流在丢失时返回无效位置，让 mod 取消位置跟随，不把光学默认眼位当成真实头部移动。

## 开机后自动可用

1. 将程序固定放在可写目录，例如 `D:\LeiaSRBridge`。退出旧版和游戏后升级文件；保持相同路径可沿用系统接入和自启动登记。
2. 在“更多 → 系统接入与启动”启用免列表接入，首次接受管理员提示；之后该项应显示“已启用”。首次配置后重启 Steam 等启动器，或重新登录 Windows。
3. 打开同一抽屉中的“开机自启动”。以后登录 Windows 后程序会在托盘运行，直接正常启动游戏即可，不需要每天再点“启用”。

两项设置独立保存：关闭自启动不会恢复原厂接入；恢复原厂接入也不会关闭自启动。如果升级解压到另一个版本目录，需要在新目录重新启用免列表接入一次，并打开自启动开关以更新启动路径。Windows“启动应用”中手动禁用此程序时，需要在那里重新允许运行。

新安装的自启动使用 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的 `LeiaSRBridge` 项（同目录旧版登记在首次启动新版时迁移到此项），命令为带引号的 EXE 绝对路径加 `--background`，不使用管理员任务或每次登录的提权脚本。启动文件位置以注册表为准，不随 `settings.ini` 迁移自动启用。免列表接入仍使用原有持久系统 PATH 配置，启动时只读取，不重新写入。

| 操作 | 全局快捷键 / 窗口控件 |
|---|---|
| X 偏移 ±0.5 mm | `Ctrl+Alt+← / →` |
| X 偏移 ±0.1 mm | `Ctrl+Alt+Shift+← / →` |
| X 偏移归零 | `Ctrl+Alt+Home` |
| 输入精确偏移 | 点击补偿数值，输入后按 Enter，范围 −30～+30 mm |
| 预测开关 | `Ctrl+Alt+F9`，重新开启恢复上次非零值 |
| 选择预测量 | 直接选择关 / 10 / 20 / 30 / 40 ms |

预测沿用已测试的水平算法：依据本地观察到的坐标变化估算速度，最多补偿 ±10 mm；重复坐标不充当新采样，反向、丢失和异常跳变时重置。固定偏移在发布副本上添加一次，不反馈到预测或保持历史。

## 头追接口范围

Leia SDK 的 `HeadPose` 包含位置、旋转、帧号和时间戳；`Head` 再包含左右眼和左右耳的三维位置。FallenFlower3D 当前仅消费 HeadPose 的位置；Yakuza 的位置跟随消费 Head 的位置，其跟踪投影另需双眼位置。

**本版提供三轴位置、三轴估算旋转、分别计算的双眼位置及估计耳位。** BOE 双眼分别由双相机计算，保留两眼各自的深度，不使用固定 IPD 合成。定位点是眼睑轮廓中心，不是瞳孔或注视方向。左右按当前屏 `wholeMat` 转换后的 X 排序；眼距不在 20～100 mm 或水平间距不足 10 mm 时不发布有效双眼，避免退化和近侧脸歧义。

旋转由两眼、鼻部和口部共五个双目面部点估算：去畸变、双目校正、三维重建、屏幕坐标转换，再用眼轴和眼口平面建立正交头部坐标系。鼻部点用于检查几何有效性。不是原厂内部九点 PnP 的直接转发；表情、遮挡及个人脸型可能影响结果，静止正视时不保证三个角恰好为零。离线测试验证坐标和数学链路，目标屏上的方向、抖动与精度仍需实测。

SDK `orientation` 使用与已检查的 Leia 实现一致的 **Rodrigues 旋转向量，单位弧度**，不是三个独立 Euler 角。后台角度读数按 ZYX 分解显示，供测试使用。调用方必须消费 orientation 才会使用旋转；现有 mod 若仅使用位置，桥接不会自动改变其相机行为。

双眼和同帧中心均应用相同的水平预测平移及全局固定补偿，再应用设备标定；不会因预测人为改变 IPD。`createRaw` 使用相同的厂商滤波结果与标定/固定补偿，仅省略桥接层预测，不代表原始相机数据。旋转不应用水平平移补偿或 40 ms 位置预测。有效旋转时，双耳为中心加旋转后的左右各 70 mm；仅双眼有效时保留沿双眼轴的耳位估算。

位置单位为毫米，原点在显示坐标系，轴为右 / 上 / 朝向观看者。完整双眼使用 SDK 调用完成的本地观察时间，**不是传感器帧号或曝光时间**，不支持 late latching。超过 250 ms、眼追进程退出或眼位丢失时，设备仍可用则向游戏提供保持/默认眼位及合成双眼/耳位，合成分量时间为 0；设备真正不可用时 C++ 接口仍返回 NaN 并报告失联。SDK 不再返回时不会靠 broker 轮询刷新双眼时间。完整通道尚未连接时，仅原有 COM 中心可用于显示和位置跟随；完整通道曾连接后退出则不会继续使用遗留 COM 值冒充新位置。

旋转有独立有效位和观察时间；新眼位或后台心跳不会续期旧旋转。面部点缺失、几何退化、双目点不匹配或超过 250 ms 时 orientation 返回 NaN。未知原厂版本只停用私有浮点读取/旋转，不阻止原有双眼转发。当前没有虹膜／瞳孔或视线模型，因此不发布注视点屏幕坐标。

## 原厂交织测试与日志

概览页“交织测试”保留静态网格/圆盘和分眼图案，采用相同的全局偏移和预测，不再自动关闭预测。把窗口移到目标屏后按 Enter；1/2/3 切换图案，Esc 退出。以目标屏原生分辨率、SDR 运行。它不另开摄像头或 MCU，也不写标定。

必要日志在 `logs/LeiaSRBridge.log`、`logs/runtime-<PID>.log` 和 `logs/StereoTest.log`；接入配置失败详情在 `logs/RuntimeIntegration.log`。原厂组件也可能产生自己的日志。

## 验证

离线检查覆盖原厂 DX11 / WARP 数值回读、预测和 fallback、参数保存/恢复、便携 COM、原版 SDK 头文件的 Head/HeadPose/EyePair ABI 与回调生命周期、DX12 录制快照、加载器、Broker 和渲染器。新增合成 SDK 验证完整 168 字节转发、导出及序号、进程身份、异常/过期样本；验证双眼坐标变换、独立深度、预测/补偿及 140 mm 耳距。包内 `verification` 保存本版结果，并核对两个现有 mod 和 Hub 三个原生模块的导入与 11 组 EXE/DLL–PDB 身份。

0.3.0 增加临时注册表中的启用/升级/恢复、保留外部修改及事务中断恢复测试；另起 EXE 与工作目录均不含 DLL 的进程，仅为该子进程设置 PATH，按名称加载全部 SR 模块，验证转发、头眼流及 WARP DX12 创建。测试不修改开发机真实系统环境、原厂 Leia 服务或游戏。尚需在目标电脑完成首次配置及 Steam 启动的实机验收。

0.4.0 增加独立 OpenCV 正向投影与桥接反算的 81 组测试，覆盖三轴 ±40°、三种距离、非零畸变和相机校正，以及屏幕坐标转换、零角/180°旋转向量、浮点读取边界、同帧校验、失效与恢复。SDK ABI 测试检查两种头追流的角度及耳位、过期旋转、无效矩阵和丢脸回退。合成测试的数值误差不代表真实人脸追踪精度。

串扰结案依据用户对 +8.0 mm / 40 ms 的实测；新增双眼及估计耳位只完成离线验证，仍需在目标电脑验收左右方向、深度和游戏跟踪投影。未修改 MCU 标定、原厂 BOE DLL、游戏或 mod 文件。桥接交织 shader 保持原有光学计算，新增可选 sRGB 转换。
